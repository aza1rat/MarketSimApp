# Правила работы с ветками

Документ описывает GitFlow команды для репозитория [MarketSimApp](https://github.com/aza1rat/MarketSimApp).

## Основные ветки

| Ветка | Назначение |
|-------|------------|
| `develop` | Интеграционная ветка для feature-задач |
| `main` | Стабильная ветка для итераций и финального релиза |

## Именование веток

| Тип | Формат                                               | Пример                |
|-----|------------------------------------------------------|-----------------------|
| Feature | `характер-изменения/номер-задачи-описание-до-6-слов` | `feat/1-some-feature` |
| Итерация | `iteration-номер`                             | `iteration-1`         |
| Релиз | `release-номер_версии`                               | `release-1.0.0`       |

### Характер изменения может быть 
| Тип | Характер изменения                                |
|-----|---------------------------------------------------|
|`feat/`| фичи                                              |
|`fix/` | исправление багов                                 |
|`docs/` | документация                                      |
|`refactor/`| чистый рефакторинг, без добавления фич            |
|`test/` | добавление недостающих тестов, рефакторинг тестов |
|`devops/` | настройка ci/cd                                   |

## Куда открывать PR

| Из ветки              | В ветку | Когда                            |
|-----------------------|---------|----------------------------------|
| `feat/N-some-feature` | `develop` | Завершена задача из kanban       |
| `iteration-N`         | `main` | Завершение раздела задач (эпика) |
| `release-X.Y.Z`       | `main` | Финальная стадия проекта         |


## Защита веток

**develop** — только через PR, минимум 1 approving review, без force-push, ветку нельзя удалить, CI checks обязательны.

**main** — только через PR, минимум 1 approving review, без force-push, ветку нельзя удалить, CI checks обязательны.

## Автоматические проверки

Workflow `.github/workflows/branch_rules.yml` проверяет на PR:

- корректность имени source-ветки;
- соответствие пары source → target правилам GitFlow.

Workflow `.github/workflows/pr_checks.yml` запускает `detekt` и `assembleDebug`.
