# 💡 Инструкция по настройке связи Android-эмулятора с локальным Docker-бэкендом (.NET)

Чтобы эмулятор успешно видел наш бэкенд на порту 5000 и Ktor не падал по TimeoutException или Cleartext Traffic, нужно подружить сетевые интерфейсы Докера, Windows и Android. Выполни следующие шаги:

## 1. Настройка Docker-контейнера

По умолчанию .NET внутри Docker слушает только localhost. Нужно заставить его принимать внешние запросы. В файле docker-compose.yml твоего бэкенда измени конфигурацию сервиса API:
* В блоке ports: замени `"5000:8080"` на `"0.0.0.0:5000:8080"`.
* В блок environment: добавь переменную: `- ASPNETCORE_URLS=http://+:8080`.
* Перезапусти контейнеры через консоль: `docker compose down`, а затем `docker compose up -d`.

## 2. Настройка Брандмауэра Windows

Windows блокирует трафик виртуального роутера эмулятора. Нужно открыть порт:
* Открой Брандмауэр Windows ➔ Дополнительные параметры ➔ Правила для входящих подключений ➔ Создать правило.
* Выбери Для порта ➔ TCP ➔ Порт: 5000 ➔ Разрешить подключение ➔ Назови правило Docker 5000 и сохрани.

## 3. Проброс портов через ADB и запуск

Чтобы эмулятор не терял пакеты, мы свяжем его локальный порт напрямую с ПК.
* Открой вкладку Terminal в Android Studio и выполни команду:

`& "$env:LocalAppData\Android\Sdk\platform-tools\adb.exe" reverse tcp:5000 tcp:5000`
* В коде Android-приложения выставляй базовый URL строго строкой: `"http://127.0.0.1"` (используй именно 127.0.0.1, а не localhost или 10.0.2.2).
* Сделай Rebuild Project и запусти
* Важно: Если закроешь/перезапустишь эмулятор, команду adb reverse... нужно будет выполнить в терминале один раз заново.
